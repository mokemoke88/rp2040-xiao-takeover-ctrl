# xiao-takeover-ctrl 仕様

XIAO RP2040 で 2つのタクトスイッチ(LB / RB)を読み、制御の乗っ取り(SEL)とレンジ指令(D0:D1)を出力する。

## 1. 信号とピン割り当て

| 信号 | 向き | XIAO ピン | GPIO | 論理 |
|---|---|---|---|---|
| D0 | 出力 | D0 | 26 | 下記「出力の意味」参照 |
| D1 | 出力 | D1 | 27 | 同上 |
| SEL | 出力 | D2 | 28 | H = 乗っ取り中、L = 元系統 |
| WARN | 出力(オンボード LED) | — | 17 | RGB LED の赤。アクティブ Low(L = 点灯 = 警告ラッチ中) |
| LB | 入力 | D9 | 4 | 外部プルアップ 10kΩ(3V3)、押下で L |
| RB | 入力 | D10 | 3 | 同上 |

- 信号名 D0/D1 と XIAO のピン名 D0/D1 を一致させ、取り違えを防ぐ
- 入力は 3V3 / GND ピンに近い右列(D9/D10)に置く
- D3、I2C1(D4/D5)、UART0(D6/D7)、D8 は予備として空けておく
- 出力 D0 / D1 / SEL は GPIO26〜28 で、SIO の1回のマスク付き書き込みで同時に変えられる

### 出力の意味(D0:D1)

| D0:D1 | 意味 |
|---|---|
| L:L | マニュアル以外 = ドライブレンジ |
| H:H | マニュアルモード待機 |
| L:H | LB パルス(200ms) |
| H:L | RB パルス(200ms) |

### 電気的な前提

- プルアップは 3V3 に接続する(RP2040 の I/O に 5V 耐性はない)
- 出力は 3.3V ロジック。相手側と GND を共通にする。相手が 5V ロジックならレベル変換を検討する
- リセット中や BOOTSEL 中は、全 GPIO が内蔵プルダウンで L になる。これは初期状態(全 L)と一致するので、外付けのプルは不要
- 入力 LB / RB は、ファームウェアの初期化で内蔵プルアップも有効にする(外付け 10kΩ と並列)。外付けのプルアップが外れても入力が浮かないようにするためと、リセット既定の内蔵プルダウンを解除するため

## 2. 状態

| 状態 | SEL | D0:D1 | 説明 |
|---|---|---|---|
| S0 | L | L:L | 解除。初期状態 |
| S1 | H | L:L | 乗っ取り中・非マニュアル |
| S2 | H | H:H | マニュアル待機 |
| P | H | L:H / H:L | パルス出力中(200ms) |
| T | 切り替え後の値 | L:L(SEL=H で `T_MANUAL` に達した後は H:H) | トグル後ロック(両入力が離されるまで) |

- 電源投入時は外部出力(SEL / D0 / D1)がすべて L(S0)、WARN は消灯。状態は保存しない

## 3. 状態遷移

### 3.1 同時押しによるトグル(S0 / S1 / S2 から)

1. LB と RB が両方押された時点から計時を始める(以下「同時押し開始」)
2. 両方を押したまま `T_TOGGLE`(2秒)に達したら:
   1. D0:D1 を L:L にする(ドライブレンジ)
   2. `T_SEL_DELAY` 待つ
   3. SEL を反転する
   4. T に移る
3. T の間は、両入力が離されるまで入力を受け付けない(WARN にはしない)。SEL=H で、両方を途切れずに押し続けて同時押し開始から `T_MANUAL`(4秒)に達したら、解放を待たずにその時点で D0:D1 を H:H にする(マニュアル待機の表示)。H:H にした後も T のままで、両入力が離されるまで入力を受け付けない
4. 両入力が離されたら、次のように遷移する:

| 条件 | 遷移先 |
|---|---|
| SEL=H かつ、同時押しが途切れずに `T_MANUAL` に達した(D0:D1 は既に H:H) | S2(D0:D1 は H:H のまま) |
| SEL=H かつ、上の条件を満たさない | S1 |
| SEL=L | S0 |

- 「同時押しを続けていた時間」は、同時押し開始から**どちらかが最初に離された時点**までで測る。例えば片方を3秒で離し、もう片方を5秒で離した場合は3秒になり、H:H にはならず S1 に移る。一度どちらかが離されると、T の間に押し直しても 4 秒の判定は再開しない
- SEL=L 側へのトグル(S1 / S2 から)では、`T_MANUAL` に達しても何もしない(D0:D1 は L:L のまま、両解放で S0)
- `T_MANUAL` への到達は `T_TOGGLE` と同じく「経過時間 ≥ 定数」で判定する(5 章)
- `T_TOGGLE` に達する前にどちらかが離された場合、トグルは起きない(S2 では 3.2 の単押しとして扱う)

安全上の考え方: D0:D1 を先に L:L にすることで、SEL で制御を切り替える瞬間の D0:D1 は必ずドライブレンジになる。元系統に戻すときも、乗っ取るときも、切り替えの時点でドライブレンジが確定している。

- SEL を反転したのと同じ時刻(1 ms 単位)には、D0:D1 を H:H にすることも、T を抜けることもしない。メインループの呼び出し間隔が空き、SEL の反転と `T_MANUAL` への到達(や両解放)が同じ時刻に処理される場合でも、H:H にするのは次の時刻になる。このため SEL が変わる出力の書き込みと D0:D1 が H:H になる出力の書き込みは必ず別になり、SEL が変わる書き込みの時点では D0:D1 = L:L になっている
- 保証しているのは「SEL の変化と D0:D1 の変化が別の出力書き込みになること」までで、SEL を反転した後に D0:D1 = L:L を保つ時間の下限は設けない。SEL の先はリレーではなく半導体スイッチで、切り替えに機械的な遅れがないことを前提にしている

### 3.2 単押し(S2 のみ受け付ける)

- S0 / S1 での単押しは無視する(ただし同時押しの始まりとしては受け付ける。3.4 の WARN 解除を参照)
- S2 では**先に押したほう**を優先入力とし、それを**離した時点**でパルスを出す(同着時の扱いは 3.5):
  - LB: D0:D1 = L:H → `T_PULSE`(200ms)→ H:H
  - RB: D0:D1 = H:L → `T_PULSE`(200ms)→ H:H
- パルス開始で P に移り、`T_PULSE` 後に S2 へ戻る
- 優先入力を離した時点でもう片方がまだ押されていれば、そちらを次の優先入力とする。その入力を離した時点で同じようにパルスを出す(P が終わってから離された場合に限る。3.3 参照)
- 同時押しが `T_TOGGLE` に達した場合は、パルスを出さず 3.1 のトグルを優先する
- 優先入力でないほう(後押し)を先に離した場合は、パルスを出さない。パルスは優先入力を離したときだけ出る
- 両方が同時に離された(1件の変化として届いた)場合は、優先入力のパルスを1回だけ出す。もう片方を次の優先入力にはせず、WARN にもしない

### 3.3 パルス出力中(P)の入力

- P の間に起きた入力の変化(押下・解放)は、すべて捨てて WARN をラッチする
  - 例: P に入る前から押されていた後押しを P の間に離した場合、その後押しのパルスは出さず WARN をラッチする
- **P の間に新たに押され**、P の終了時点でもまだ押されているボタンは、WARN をラッチし、一度離されるまで無視する(同時押しの判定にも数えない)
- P に入る前から押され続けているボタン(3.2 の「次の優先入力」)は、この扱いの対象外
- 「離されるまで無視」の状態にあるボタン(この節の無視)が P の間に離されても、操作とみなさず WARN にしない
  - 4.1 の起動時の無視は、この状況にはならない。起動時は S0 で、P に入るには S2 を経る必要があり、S2 へは T で両入力が離される(= 無視が解ける)ことでしか移れないため。実装は無視の理由を区別せずに扱っている

### 3.4 WARN

- 表示: オンボード RGB LED の赤を点灯する(7 章)
- ラッチ条件: 3.3 に書いたもの、およびウォッチドッグによる再起動(6.1)
- 解除条件: 押下を受け付けた瞬間
  - S0 / S1 / S2 での押下が対象。S0 / S1 での押下も同時押しの始まりとして受け付けているので、解除の対象に含む
  - P / T の間の押下と、「離されるまで無視」の状態にあるボタンの押下は対象外

### 3.5 同着時の優先

- LB と RB の押下が同じ除去窓の中で起き、チャタリング除去後に1件の変化として届いた場合は、**LB を先押し**とみなす
- 優先側は定数1か所で決める。RB 優先に切り替える方法を、その定義箇所のコメントに書いておく

### 3.6 同時に届いた変化の処理順

チャタリング除去後の1件の変化で2ビットが同時に変わっていた場合は、2つの変化が同じ時刻に次の順で起きたものとして処理する。

1. 解放を先に処理する。両方の解放なら、S2 の優先入力でないほうを先にする(3.2 の同時解放の扱いになる)
2. 次に押下を処理する。両方の押下なら、3.5 の同着優先側を先にする

例えば S2 で、優先入力の解放と他方の押下が1件で届いた場合は、優先入力のパルスが始まった後の押下になり、3.3 により WARN をラッチしてその押下は離されるまで無視する(パルスが増える方向には倒れない)。

## 4. チャタリング除去(PIO)

制御ロジックを単純にするため、チャタリング除去は PIO で行い、CPU は除去済みの状態変化だけを受け取る。

- PIO0 の SM を1つ使い、LB / RB の2ピンをまとめて監視する(`in pins, 2`、in_base=GPIO3。bit0=RB、bit1=LB)
  - 2ピンを1つの SM で扱うことで、状態変化が発生順に1本の FIFO に並び、先押しの判定が FIFO の順序だけで済む
  - このためには LB と RB が連続した GPIO である必要がある。ピン割り当てを変えるときは注意する
- 方式は「安定待ち」: 変化を見つけたら一定間隔で何回か読み直し、新しい値のままだった場合に限って確定し、RX FIFO に 2ビットの状態を push する。途中で元に戻ったらノイズとして捨てる
  - 「変化したら即座に通知し、一定時間は見ない」方式は採らない。単発のノイズも押下として拾うため
- push はブロッキング(FIFO が満杯なら SM が待つ)とし、変化を取りこぼさない
- CPU 側は、メインループで RX FIFO をポーリングして受け取る(当面の方針)。FIFO が空でない限り読み出しを続け、溜まっている変化を発生順にすべて処理する
  - SM の IRQ による受け取りは採らない(必要になったら見直す)
- CPU 側は受け取った値を前回値と比べ、変化したビットから押下・解放を判定する。2ビットが同時に変化していた場合は 3.5 / 3.6 に従う
- 2ピンをまとめて比較するため、片方のピンが除去時間(約 20 ms)より短い周期で変化し続けると、その間はもう片方のピンの変化も確定せず、届かない。出力は最後に確定した状態のまま動かず、新たなトグルやパルスが起きる方向には働かないので、危険側ではない
  - 読み取りは一定間隔の標本化なので、ノイズの周期が読み直しの間隔とちょうど同期している場合は「安定」とみなすことがある(安定待ち方式一般の限界)

### 4.1 起動時の状態

- 起動後の最初の push は、ボタンが押されていてもいなくても必ず起動時の(除去済みの)状態を表す。SM の確定値 X の初期値を、ピンから読める値(0〜3)のどれとも違う値にしておくことで実現する
- 起動時に押されていたボタンは、一度離されるまで無視する(3.3 の無視と同じ扱い。同時押しの判定にも数えない。WARN にはしない)。押したまま電源を入れても、トグルやパルスは起きない
- ウォッチドッグによる再起動後も同じ扱いになる

## 5. タイミング定数

| 名前 | 値 | 状態 |
|---|---|---|
| `T_TOGGLE` | 2000 ms | 確定 |
| `T_MANUAL` | 4000 ms(同時押し開始から) | 確定 |
| `T_PULSE` | 200 ms | 確定 |
| `T_SEL_DELAY` | 10 ms | 暫定。相手側が D0:D1 を取り込むのに必要な時間以上にする。実機で確認する |
| `T_DEBOUNCE` | 約 20 ms | 暫定(提案値)。PIO のクロック分周比と読み直しの回数で決まる。現在の設定では、確定した変化が届くのは変化から 21.25〜22 ms 後 |

定数はコード内の1か所で定義し、変えやすくする。

時間の境界の判定(時刻はミリ秒単位に切り捨てた値で扱う):

- `T_TOGGLE` / `T_MANUAL` は「経過時間 ≥ 定数」で判定する。「`T_TOGGLE` に達したら」は同時押し開始からの経過が 2000 ms 以上になった時点、「`T_MANUAL` に達したら」は同時押しが途切れずに同時押し開始から 4000 ms 以上になった時点(その時点のメインループの周で H:H にする。3.1)
- `T_PULSE` / `T_SEL_DELAY` は「経過時間 > 定数」で判定する。時刻はメインループの各周の先頭で1回読んで切り捨てたもので、開始時刻が最大 1 ms 早く記録されうるため、「≥」では実際の差が定数を下回る場合がある
  - 保証するのは、開始した周と終了した周の、先頭で時刻を読んだ時点(サンプリング時刻)の差が定数を超えること。その差は、定数より長く、定数 + 1 ms + メインループ1周分より短い(例: パルスは 200 ms 超 〜 約 201 ms)
  - 実際にピンが変わるのは各周の出力処理の時点なので、ピンの変化の間隔は、2つの周でサンプリングから出力までにかかった処理時間の差(µs 程度)だけずれうる

## 6. ウォッチドッグ

- 有効にするかどうかをビルド時に選べるようにする
- ウォッチドッグでリセットされると、外部出力がすべて L(SEL=L で元系統に戻り、D0:D1=L:L でドライブレンジ)になる
- この場合 D0:D1 と SEL は同時に変わり、3.1 の順序どおりにはならない。ただし行き着く先は元系統とドライブレンジなので、安全側の考え方とは矛盾しない
- タイムアウトは 100 ms。メインループの毎周でウォッチドッグを更新する

### 6.1 ウォッチドッグによる再起動の表示

- ウォッチドッグのタイムアウトで再起動した場合は、WARN(赤)を点灯した状態で起動する。解除条件は通常の WARN と同じ(押下を受け付けた瞬間。3.4)
- 判定には Pico SDK の `watchdog_enable_caused_reboot()` を使う。リセット理由のレジスタに加えて、`watchdog_enable()` がスクラッチレジスタ 4 に書く目印を確認するもので、`watchdog_enable()` で開始したウォッチドッグのタイムアウトだけを対象にする意図
  - 電源投入とリセットボタン(RUN ピン)による起動では、リセット理由が消えるので対象外
  - SDK の `watchdog_reboot()` による再起動では、目印が消されるので対象外(SDK のソースで確認)
  - UF2 の書き込み後の再起動は SDK の `watchdog_reboot()` ではなくブート ROM が行う。SDK のドキュメントはこの場合も対象外になると書いているが、ブート ROM の挙動は未検証
- 起動時に押されていたボタン(4.1 で無視するもの)の解放では解除しない

### 6.2 panic 後の流れ

panic(`hard_assert` の失敗や、PIO の命令メモリ・ステートマシンが確保できなかった場合を含む)が起きたときは、次の順に進む。

1. 外部出力を安全側に倒す。3.1 と同じ順序で、D0:D1 を L:L にし、SEL が H なら `T_SEL_DELAY` 以上待ってから SEL を L にする。WARN LED は変えない
   - 待ちはクロックサイクル数を数える空ループで行う(タイマーや割り込みに依存しない。クロックが既定より遅い状態なら待ちが長くなるだけ)
2. 緑 LED(正常動作表示。7 章)を消灯して停止する
3. ウォッチドッグが有効なら、停止中は更新されないので、タイムアウト(100 ms)後にリセットされる
4. 再起動後は 6.1 により WARN(赤)が点いた状態で始まる
5. 初期化がすべて成功すれば、メインループに入る直前に緑が点く

- 出力の初期化より前の panic では、ピンがまだ出力になっていないので 1・2 は何も変えない。外部出力はリセット直後の状態(内蔵プルダウンで L)のまま
- ウォッチドッグを開始する前(初期化中)の panic では、リセットされずに停止したままになる。外部出力は 1 により SEL = L、D0:D1 = L:L
- ウォッチドッグが無効なビルドでは、panic 後は 1 の状態で停止したままになる
- HardFault など panic を経由しない停止では、1・2 の処理は行われない(出力はその時点のまま、緑は点いたまま止まる)。ウォッチドッグが有効ならリセットで復帰し、外部出力はすべて L になり、再起動後は 6.1 のとおり赤が点く
- panic 時の処理を差し込めるのは Pico SDK の panic フック(`PICO_PANIC_FUNCTION`)を使っているため。デバッグビルド(`NDEBUG` なし)では `hard_assert` が通常の `assert` になり、panic を経由しないので緑は消えない(リリースビルドが既定)

## 7. オンボード LED

| LED | GPIO | 用途 |
|---|---|---|
| RGB 赤 | 17 | WARN(ラッチ中は点灯) |
| RGB 緑 | 16 | 正常動作表示(初期化に成功してメインループに入ると点灯、panic で消灯。6.2) |
| RGB 青 | 25 | 使わない(消灯固定) |
| NeoPixel | 12(電源 11) | 使わない(電源を入れない) |

- RGB LED はアクティブ Low なので、消灯は H 出力。起動時の初期化で赤・緑・青とも H にしてから処理を始める
- 緑は、出力・PIO・ウォッチドッグの設定がすべて成功し、メインループに入る直前に点灯する。初期化の途中で止まった場合は点かない
- 乗っ取り状態やマニュアルモードの表示は行わない。元基板側の LED で確認できるため
- SDK 既定の `PICO_DEFAULT_LED_PIN` は 25(青)なので、SDK のサンプル由来のコードをそのまま使わない
