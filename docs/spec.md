# xiao-takeover-ctrl 仕様

XIAO RP2040 で 2つのタクトスイッチ(LB / RB)を読み、制御の乗っ取り(SEL)とレンジ指令(D0:D1)を出力する。

## 1. 信号とピン割り当て

| 信号 | 向き | XIAO ピン | GPIO | 論理 |
|---|---|---|---|---|
| D0 | 出力 | D0 | 26 | 下記「出力の意味」参照 |
| D1 | 出力 | D1 | 27 | 同上 |
| SEL | 出力 | D2 | 28 | H = 乗っ取り中、L = 元系統 |
| WARN | 出力(オンボード LED) | — | 17 | RGB LED の赤。アクティブ Low(L = 点灯 = 警告ラッチ中) |
| LB | 入力 | D9 | 4 | 外部プルアップ 10kΩ(3V3)、押下で L |
| RB | 入力 | D10 | 3 | 同上 |

- 信号名 D0/D1 と XIAO のピン名 D0/D1 を一致させ、取り違えを防ぐ
- 入力は 3V3 / GND ピンに近い右列(D9/D10)に置く
- D3、I2C1(D4/D5)、UART0(D6/D7)、D8 は予備として空けておく
- 出力 D0 / D1 / SEL は GPIO26〜28 で、SIO の1回のマスク付き書き込みで同時に変えられる

### 出力の意味(D0:D1)

| D0:D1 | 意味 |
|---|---|
| L:L | マニュアル以外 = ドライブレンジ |
| H:H | マニュアルモード待機 |
| L:H | LB パルス(200ms) |
| H:L | RB パルス(200ms) |

### 電気的な前提

- プルアップは 3V3 に接続する(RP2040 の I/O に 5V 耐性はない)
- 出力は 3.3V ロジック。相手側と GND を共通にする。相手が 5V ロジックならレベル変換を検討する
- リセット中や BOOTSEL 中は、全 GPIO が内蔵プルダウンで L になる。これは初期状態(全 L)と一致するので、外付けのプルは不要

## 2. 状態

| 状態 | SEL | D0:D1 | 説明 |
|---|---|---|---|
| S0 | L | L:L | 解除。初期状態 |
| S1 | H | L:L | 乗っ取り中・非マニュアル |
| S2 | H | H:H | マニュアル待機 |
| P | H | L:H / H:L | パルス出力中(200ms) |
| T | 切り替え後の値 | L:L | トグル後ロック(両入力が離されるまで) |

- 電源投入時は外部出力(SEL / D0 / D1)がすべて L(S0)、WARN は消灯。状態は保存しない

## 3. 状態遷移

### 3.1 同時押しによるトグル(S0 / S1 / S2 から)

1. LB と RB が両方押された時点から計時を始める(以下「同時押し開始」)
2. 両方を押したまま `T_TOGGLE`(2秒)に達したら:
   1. D0:D1 を L:L にする(ドライブレンジ)
   2. `T_SEL_DELAY` 待つ
   3. SEL を反転する
   4. T に移る
3. T の間は、両入力が離されるまで入力を受け付けない(WARN にはしない)
4. 両入力が離されたら、次のように遷移する:

| 条件 | 遷移先 |
|---|---|
| SEL=H かつ、同時押しを `T_MANUAL`(4秒)以上続けていた | S2(D0:D1 を H:H にする) |
| SEL=H かつ、上の条件を満たさない | S1 |
| SEL=L | S0 |

- 「同時押しを続けていた時間」は、同時押し開始から**どちらかが最初に離された時点**までで測る。例えば片方を3秒で離し、もう片方を5秒で離した場合は3秒になり、S2 には移らない
- `T_TOGGLE` に達する前にどちらかが離された場合、トグルは起きない(S2 では 3.2 の単押しとして扱う)

安全上の考え方: D0:D1 を先に L:L にすることで、SEL で制御を切り替える瞬間の D0:D1 は必ずドライブレンジになる。元系統に戻すときも、乗っ取るときも、切り替えの時点でドライブレンジが確定している。

### 3.2 単押し(S2 のみ受け付ける)

- S0 / S1 での単押しは無視する(ただし同時押しの始まりとしては受け付ける。3.4 の WARN 解除を参照)
- S2 では**先に押したほう**を優先入力とし、それを**離した時点**でパルスを出す(同着時の扱いは 3.5):
  - LB: D0:D1 = L:H → `T_PULSE`(200ms)→ H:H
  - RB: D0:D1 = H:L → `T_PULSE`(200ms)→ H:H
- パルス開始で P に移り、`T_PULSE` 後に S2 へ戻る
- 優先入力を離した時点でもう片方がまだ押されていれば、そちらを次の優先入力とする。その入力を離した時点で同じようにパルスを出す(P が終わってから離された場合に限る。3.3 参照)
- 同時押しが `T_TOGGLE` に達した場合は、パルスを出さず 3.1 のトグルを優先する

### 3.3 パルス出力中(P)の入力

- P の間に起きた入力の変化(押下・解放)は、すべて捨てて WARN をラッチする
  - 例: P に入る前から押されていた後押しを P の間に離した場合、その後押しのパルスは出さず WARN をラッチする
- **P の間に新たに押され**、P の終了時点でもまだ押されているボタンは、WARN をラッチし、一度離されるまで無視する(同時押しの判定にも数えない)
- P に入る前から押され続けているボタン(3.2 の「次の優先入力」)は、この扱いの対象外

### 3.4 WARN

- 表示: オンボード RGB LED の赤を点灯する(7 章)
- ラッチ条件: 3.3 に書いたもの
- 解除条件: 押下を受け付けた瞬間
  - S0 / S1 / S2 での押下が対象。S0 / S1 での押下も同時押しの始まりとして受け付けているので、解除の対象に含む
  - P / T の間の押下と、「離されるまで無視」の状態にあるボタンの押下は対象外

### 3.5 同着時の優先

- LB と RB の押下が同じ除去窓の中で起き、チャタリング除去後に1件の変化として届いた場合は、**LB を先押し**とみなす
- 優先側は定数1か所で決める。RB 優先に切り替える方法を、その定義箇所のコメントに書いておく

## 4. チャタリング除去(PIO)

制御ロジックを単純にするため、チャタリング除去は PIO で行い、CPU は除去済みの状態変化だけを受け取る。

- PIO0 の SM を1つ使い、LB / RB の2ピンをまとめて監視する(`in pins, 2`、in_base=GPIO3。bit0=RB、bit1=LB)
  - 2ピンを1つの SM で扱うことで、状態変化が発生順に1本の FIFO に並び、先押しの判定が FIFO の順序だけで済む
  - このためには LB と RB が連続した GPIO である必要がある。ピン割り当てを変えるときは注意する
- 方式は「安定待ち」: 変化を見つけたら一定間隔で何回か読み直し、新しい値のままだった場合に限って確定し、RX FIFO に 2ビットの状態を push する。途中で元に戻ったらノイズとして捨てる
  - 「変化したら即座に通知し、一定時間は見ない」方式は採らない。単発のノイズも押下として拾うため
- push はブロッキング(FIFO が満杯なら SM が待つ)とし、変化を取りこぼさない
- CPU 側は、メインループで RX FIFO をポーリングして受け取る(当面の方針)。FIFO が空でない限り読み出しを続け、溜まっている変化を発生順にすべて処理する
  - SM の IRQ による受け取りは採らない(必要になったら見直す)
- CPU 側は受け取った値を前回値と比べ、変化したビットから押下・解放を判定する。2ビットが同時に変化していた場合は 3.5 に従う

## 5. タイミング定数

| 名前 | 値 | 状態 |
|---|---|---|
| `T_TOGGLE` | 2000 ms | 確定 |
| `T_MANUAL` | 4000 ms(同時押し開始から) | 確定 |
| `T_PULSE` | 200 ms | 確定 |
| `T_SEL_DELAY` | 10 ms | 暫定。相手側が D0:D1 を取り込むのに必要な時間以上にする。実機で確認する |
| `T_DEBOUNCE` | 約 20 ms | 暫定(提案値)。PIO のクロック分周比と読み直しの回数で決まる |

定数はコード内の1か所で定義し、変えやすくする。

## 6. ウォッチドッグ

- 有効にするかどうかをビルド時に選べるようにする
- ウォッチドッグでリセットされると、外部出力がすべて L(SEL=L で元系統に戻り、D0:D1=L:L でドライブレンジ)になる
- この場合 D0:D1 と SEL は同時に変わり、3.1 の順序どおりにはならない。ただし行き着く先は元系統とドライブレンジなので、安全側の考え方とは矛盾しない

## 7. オンボード LED

| LED | GPIO | 用途 |
|---|---|---|
| RGB 赤 | 17 | WARN(ラッチ中は点灯) |
| RGB 緑 | 16 | 使わない(消灯固定) |
| RGB 青 | 25 | 使わない(消灯固定) |
| NeoPixel | 12(電源 11) | 使わない(電源を入れない) |

- RGB LED はアクティブ Low なので、消灯は H 出力。起動時の初期化で赤・緑・青とも H にしてから処理を始める
- 乗っ取り状態やマニュアルモードの表示は行わない。元基板側の LED で確認できるため
- SDK 既定の `PICO_DEFAULT_LED_PIN` は 25(青)なので、SDK のサンプル由来のコードをそのまま使わない
